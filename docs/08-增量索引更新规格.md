# 增量索引更新规格（第十九轮）

> 需求原文：「每次打开时更新搜索索引文件，一直使用情况下，给出新文件加入索引的方案，并实现，要求不能增加系统负担和使用体验。」
> 用户补充确认：「关闭时更新也可以，只要能实时查到最新的就可以」——落盘时机放宽为关闭时 + 启动差量后，**不做运行期周期性写盘**。

## 1. 现状与缺口

秒搜索引（`instant.rs`/`mft.rs`，见 docs/06）的更新链路：

| 环节 | 现状 | 缺口 |
|---|---|---|
| 使用中新增/删除/改名 | ReadDirectoryChangesW 监控（`monitor_loop`）实时应用进内存索引 | 无 ✓ |
| 使用中的变更持久化 | **从不落盘**（落盘点仅「构建完成」「监控故障重扫后」两处） | 下次启动加载的是构建完成时刻的快照 |
| 关闭期间的变更 | 无任何机制覆盖 | RDC 只能看到打开后的事件，**这部分变更永久缺失**，直到监控故障触发全量重扫 |
| 打开时 | 直接加载快照，内容可能陈旧 | 违背「打开时能查到最新」 |

## 2. 方案选型

关闭期间变更的补齐机制对比：

| 方案 | 负担 | 结论 |
|---|---|---|
| A. 启动全量重建（MFT 重读） | 顺序读数 GB + 全量解析，分钟级磁盘/CPU | ✗ 违背「不增加负担」 |
| B. 启动全盘差分扫描 | 同 A（枚举本身是重建成本的 90%） | ✗ |
| **C. USN Journal 启动差量回放** | 读 journal 增量（日常 KB~MB 级）+ 增量应用（秒级、后台线程） | ✓ 采用 |

USN Journal（$UsnJrnl）是 NTFS 内核维护的变更日志，纯 Win32 API（`FSCTL_QUERY_USN_JOURNAL`/`FSCTL_READ_USN_JOURNAL`），零第三方依赖，符合「不依赖外部程序」铁律。程序强制管理员运行（十四轮），卷设备 GENERIC_READ 打开无障碍。

## 3. 设计

### 3.1 数据结构变更

- `Entry` 增加 `frn: u64`（File Reference Number 低 48 位；0 = 未知）。**只给目录填值**（文件不需要——USN 删除事件按 父FRN+名字 定位）。MFT 构建与快照加载时填充；RDC 新增目录填 0（其 CREATE 记录会在下次启动差量中回放补齐 frn）。
- `Inner` 增加 `frn_dir: HashMap<u64, u32>`（目录 FRN → 条目下标），供 USN 事件的 ParentFRN 定位。
- `push_entry` 增加 `frn` 参数；目录且 frn≠0 时同步登记 `frn_dir`。

### 3.2 快照格式 v3（WFMIDX2）

- magic：`WFMIDX1\0` → `WFMIDX2\0`（旧快照直接判失效，重建一次，flog 留档）。
- 每根头部追加：`last_usn: u64` + `journal_id: u64`（该根上次差量处理到的 USN 位置与 journal 实例标识）。
- 目录条目编码在名字后追加 `frn: u64`（文件条目格式不变）。
- `last_usn` 来自内存态 `USN_STATE: Mutex<HashMap<u32,(u64,u64)>>`（root_idx → (last_usn, journal_id)），写快照时逐根查询。

### 3.3 启动差量（catch-up）

`load_index` 成功后，对每根满足 `last_usn>0 && journal_id≠0 && 盘根` 的根启动 catch-up 线程：

1. **先等 RDC 句柄打开**（`monitor_loop` 打开成功后置 `MON_OPEN[root]=true`；catch-up 轮询等待，≤5s）。顺序铁律：RDC 先开 → 覆盖「现在→关闭」；差量覆盖「上次 last_usn→现在」→ 并集无洞，重叠区由幂等应用吸收。
2. 打开卷设备 `\\.\X:`，`FSCTL_QUERY_USN_JOURNAL` 取 (JournalID, NextUsn, FirstUsn)。校验：JournalID 一致且 `last_usn ≥ FirstUsn` 且 `last_usn ≤ NextUsn`；不一致 = journal 被裁剪/重建 → **该根全量重建**（MFT 直读优先，回退枚举；重建前先查 NextUsn 写入 USN_STATE，重建期间新事件由下次差量覆盖）。
3. `FSCTL_READ_USN_JOURNAL` 从 last_usn 顺序读记录（1MB 缓冲循环），逐条应用：
   - Reason 含 `FILE_CREATE`/`RENAME_NEW_NAME` → **增**（父 FRN 定位父 idx → stat 补 size/mtime → find_child 已存在则更新（幂等，防运行期 RDC 已应用过的重复回放）否则 push；目录：登记 dir_paths/path_idx + `frn_dir[记录FRN]=idx` + `walk_insert` 子树（改名目录的子项无 journal 记录，须重枚举））。
   - Reason 含 `FILE_DELETE`/`RENAME_OLD_NAME` → **删**（父 FRN + 记录名 → `unlink_child`；目录经 Entry.frn 联动清 frn_dir）。
   - 其余 Reason（DATA_*、基本属性变化等）忽略（size/mtime 陈旧可接受，运行期由 RDC 实时覆盖）。
4. 完成后：`USN_STATE[root] = (NextUsn, JournalID)` → flog 统计 → `save_index()`（启动场景必然超过 60s 限流窗口，允许落盘）。
5. 期间若 `rescan_volume` 发生（`RESCAN_GEN` 计数器变化）→ 放弃本线程剩余差量（重扫已含全量状态并自行更新 last_usn）。

### 3.4 各构建路径的 last_usn 维护

- **MFT 构建**（`build_and_monitor`）：查询 journal 在 **MFT 读取之前**（T_q0 < T_mft，宁可回放少量重复也不漏）→ `USN_STATE = (NextUsn@T_q0, jid)`。查询失败（非 NTFS/无 journal）→ (0,0) = 该根不参与差量。
- **文件夹枚举回退构建**：frn 全 0 → 差量无法定位父 → USN_STATE = (0,0)（保持现有行为）。
- **`rescan_volume`（监控故障恢复）**：升级为盘根优先 MFT 重建（frn 完整 ✓）；查询 NextUsn 在重扫前 → 更新 USN_STATE。枚举回退时置 (0,0)。
- **差量完成**：NextUsn@读取终点。

### 3.5 落盘时机（按用户确认收敛）

1. **关闭时**：main.rs 退出路径（`run()` 返回后）调 `instant::save_index()`——持久化本次会话 RDC 积累的变更。强杀进程不执行（best-effort，缺口由下次启动差量补齐）。
2. **启动差量完成后**：快照 + last_usn 一并前推，下次差量范围收敛。
3. 既有两点保留：构建完成时、监控故障重扫后。**不做运行期周期性落盘**。

### 3.6 正确性论证

- **无洞**：RDC 覆盖 [打开, 关闭]；差量覆盖 [last_usn, 差量读取终点]；两点衔接（读取终点 > RDC 打开点）。关闭后的变更全部在 journal，下次打开回放。
- **幂等**：差量回放范围与上次会话 RDC 已应用的事件重叠（last_usn 是上次差量终点而非关闭点）→ add 先 find_child，存在则更新不 push；delete 目标不存在则跳过 → 重复回放无副作用。
- **journal 被裁剪**：FirstUsn 越过 last_usn → 重建，宁可慢不出错。
- **FRN 复用**：记录号可被复用，但删除事件已同步清 frn_dir；insert 覆盖旧值为兜底。

### 3.7 负担评估

- 启动差量：读 journal 尾部增量（日常 KB~MB），应用秒级，后台线程不阻塞 UI；无全盘 IO。
- 运行期：RDC 既有机制零新增；无周期写盘（150MB 快照不在运行期反复刷盘）。
- 一次性成本：v2 快照首次加载失效触发一次重建（此后长期受益）。

## 4. 测试

1. **USN 记录解析**（纯函数单测）：合成 V2 记录字节流（含多记录、对齐填充、reason/FRN 字段断言）。
2. **快照 v3 往返**：现有 roundtrip 测试扩展——目录 frn、last_usn/journal_id 编解码一致性；v1 魔数拒绝加载。
3. **差量应用幂等**：对测试树先 apply_event 增加，再以相同事件回放 USN 差量 → 条目数不变（防重复 push）。
4. **端到端**：真实卷 diag 测试（查询 C: journal 元数据合法性）+ 部署后实测：建索引 → 关程序 → 新建文件 → 重开 → 搜索命中。
