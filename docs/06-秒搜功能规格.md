# 06 秒搜（Everything 式即时搜索）功能规格

> 依据《Everything-搜索与索引-逆向分析.md》（下称"报告"）的原理复刻。
> **硬性要求：不依赖任何第三方程序/进程实现功能**（第八轮曾以 IPC 借用
> Everything 索引，已移除；一切能力独立实现）。

## 1. 原理对应关系（报告 → 实现）

| 报告结论 | 本实现 |
|---|---|
| §4.4 搜索 = 紧凑全表线性扫描 + ASCII 大小写折叠快路径（速度来自数据布局而非算法） | 自建索引为连续 `Vec<Entry>`（名字/父指针/大小/mtime 内联），扫描时逐条 ASCII 折叠匹配，非 ASCII 走完整折叠 |
| §3.2 MFT 直读：`\\.\X:` → `FSCTL_GET_NTFS_VOLUME_DATA` → 顺序读 `$MFT` → USA fixup → `$FILE_NAME`/`$DATA` | **NTFS 盘根首选路径**（`src/mft.rs`，零第三方依赖；需管理员，详见 §3） |
| §3.5 非 NTFS / 无权限时的文件夹索引模式：`FindFirstFileW` 递归枚举 + `ReadDirectoryChangesW` 监控 | MFT 不可用时的回退路径（自定义目录根亦走此路径） |
| §3.4 USN 增量 | 以 `ReadDirectoryChangesW` 等价替代（文件夹索引模式同款） |
| §4.2 查询语法 | 子集：AND/OR/NOT/通配符/`ext:`/`size:`/`dm:`/`path:`/`file:`/`folder:` |
| 报告 §4.1 Everything IPC | **已移除**（依赖第三方进程，违反独立实现原则） |

## 2. 后端选择

```
search_commit(query)
  ├─ 自建全盘索引就绪（构建或从落盘加载完成）
  │     → 内存全表线性扫描，毫秒级出结果
  └─ 未就绪 → 旧递归搜索（tasks.rs，当前目录子树）
```

- `search-root` 标签分别显示 `全盘索引` / 原当前目录，UI 结构不变。
- 就绪判定 `INDEX_READY`：全卷构建完成 **或** 落盘索引加载完成（两条路径都必须置位）。

## 3. 自建全盘索引

### 3.1 构建（每固定盘一线程）

- 卷发现：`GetLogicalDrives` + `GetDriveTypeW == DRIVE_FIXED`
- **NTFS 盘根 → MFT 直读**（`src/mft.rs::enum_mft`，报告 §3.2 复刻）：
  1. `CreateFileW("\\.\X:", GENERIC_READ)`（需管理员令牌；失败即回退）
  2. `DeviceIoControl(FSCTL_GET_NTFS_VOLUME_DATA)` → `BytesPerFileRecordSegment` /
     `MftStartLcn` / `MftValidDataLength` / `BytesPerSector`
  3. 自 `MftStartLcn × BytesPerCluster` 起顺序流式读 $MFT（16MB 块，
     扇区对齐包装兼容 4Kn 盘）
  4. 逐条解析 1024B 记录：`FILE` 签名 → **USA fixup**（扇区尾序列号校验+回填，
     不实现则读不对任何多扇区记录）→ 跳过元文件（记录 <24）、未使用、扩展记录
     （base≠0）→ `$FILE_NAME`（命名空间优先级 Win32(1) > Win32&DOS(3) > POSIX(0) >
     DOS 别名(2)；名字含 `/` 丢弃）+ `$DATA`（非驻留 realSize@0x38 / 驻留 valueLen）
  5. FRN 父子图从卷根（parent 引用 5）BFS 定可达性：$Extend 子项等孤儿自动剔除；
     活跃槽位顺序编号后装配进全局索引，目录路径从根 BFS 登记
- **回退路径 → 文件夹枚举**（MFT 打开失败 / 非 NTFS / 自定义目录根）：
  `read_dir` 迭代式 DFS（显式栈），跳过 junction/symlink（防环铁律），深度上限 256，
  每条目零额外系统调用取 `DirEntry::metadata()`
- 索引内容：`Vec<Entry{ name, parent, sibling, dir, dead, size, mtime }>`
  + `first_child: HashMap<dir_idx, u32>`（兄弟链）
  + `dir_paths: HashMap<dir_idx, Arc<str>>`（目录全路径：结果拼装 / path: 匹配 / 增量定位）
- 构建期间搜索照常可用：未就绪的查询自动降级旧递归搜索。
- 配置 `index_drives`（TOML 数组，如 `["D:", "E:"]`）可收窄范围；默认全部固定盘。
  诊断钩子 `WFM_INDEX_DRIVES` 环境变量优先级最高（同时强制跳过落盘读/写，
  防止诊断沙箱污染真实索引）。

### 3.2 增量监控（每卷一线程）

- `CreateFileW(卷根, FILE_LIST_DIRECTORY)` + `ReadDirectoryChangesW`
  （递归子树，缓冲 8MB，`FILE_NOTIFY_CHANGE_FILE_NAME | FILE_NOTIFY_CHANGE_SIZE`）
- 事件分派（与报告 §3.4 的 reason 分派同构）：
  - `ADDED` → 插入（目录则连带枚举其子树）
  - `REMOVED` / `RENAMED_OLD_NAME` → 兄弟链摘除（目录连子树）；RENAME 从简：删+增
  - `MODIFIED`（SIZE 事件）→ 定位条目后补 stat，刷新 size/mtime
- 缓冲溢出/句柄失效 → 该卷**全量重扫**（限流落盘，≥60s 一次）
- 限制：删除的文件不会进结果（索引实时摘除）。

### 3.3 索引落盘（本轮新增）

- 路径：**程序同级目录** `wfm_index.bin`（`current_exe().parent()`）；
  写入用 `wfm_index.bin.tmp` + rename 原子替换。
- 格式：`"WFMIDX1\0"` 魔数 + 根列表（路径 UTF-8 + **卷序列号**）+ 条目数组
  （parent u32 / dir u8 / size u64 / mtime i64 / 名字 UTF-16 长度前缀）。
  根列表按根条目下标排序，与保存序一致；活跃条目重映射下标（dead 洞剔除）。
- 触发时机：全部卷构建完成（INDEX_PENDING 归零）+ 监控重扫后（限流）。
- 加载（启动时优先于构建）：
  - 校验：魔数 / 根路径逐项一致 / **卷序列号一致**（`GetVolumeInformationW`）/
    根条目名与路径一致 / 下标界内；任一失败 → 静默重建
  - 加载后重建 first_child（保存序头插）与 dir_paths（从根 BFS），置 `INDEX_READY`，
    并为每根启动监控线程
- 诊断 env（`WFM_INDEX_DRIVES`）模式下跳过读/写落盘。

## 4. 查询语法（子集，报告 §4.2）

| 语法 | 语义 |
|---|---|
| `a b` | AND（默认子串匹配文件名，大小写不敏感） |
| `a|b` | OR（顶层按 `\|` 切分成备选组） |
| `!a` | NOT |
| `*` `?` | 通配符（term 含通配符时整名 fnmatch） |
| `ext:txt;md` | 扩展名列表 |
| `size:>10mb` `<5kb` `3000` `empty/tiny/small/medium/large/huge/gigantic` | 大小（报告 §4.2.5 同款边界） |
| `dm:today/yesterday/thisweek/thismonth/thisyear/2024/2024-05` + `> < >= <=` | 修改时间 |
| `path:term` | 匹配父目录路径（=全路径去掉文件名，语义覆盖所有后代） |
| `file:` `folder:`（可取反） | 只文件 / 只目录 |
| `case:` `content:` `child:` 等 | 未实现 → 按字面量处理（Everything 对未知函数同样回退字面量） |

## 5. 限制（诚实边界）

1. MFT 直读需**管理员运行**：非提权打开 `\\.\X:` 被拒，自动回退文件夹枚举
   （约 100k 条/秒，全盘数百万条目需数十秒后台完成；期间查询降级旧递归）。
   提权运行时 MFT 顺序读显著快于枚举（理论 GB 级/秒）。
2. MFT 场景下 `mtime` 取自 `$FILE_NAME` 修改时间（Windows 资源管理器同源）。
3. 落盘索引的卷序列号只取 32 位（GetVolumeInformationW）；重分区/换盘自动重建。
4. `path:` 语义为「父目录路径匹配」，覆盖全部后代但与 Everything 逐字符全路径
   匹配在极端边界（匹配项横跨文件名与目录名）略有差异。

## 8. 健全性修复轮（「搜索无结果」排查，2026-11-15）

用户反馈搜索无结果。排查发现三个真实缺陷，全部修复（65 单测全绿）：

1. **加载根匹配按位置比较**（致命）：保存序 = 根下标序（线程调度决定，实测为
   `D:,C:,G:,E:,F:`），加载却与 resolve_roots 的盘符序逐位置比较 → 必然不匹配 →
   **每次启动都静默重建**，落盘索引形同虚设。修复：按路径集合匹配，顺序无关。
2. **构建中途的监控重扫会把半成品快照写盘**（用户踩到的根源）：`LAST_SAVE` 初始为 0，
   任一根的监控一启动即失效（易变卷实测必现）→ 重扫 → 限流落盘立即放行 → 写出
   「5 根 6 条目」的近空快照；下次启动它通过根路径+卷序列号校验被秒加载 →
   INDEX_READY → 永远搜不到东西。修复：`save_index_rate_limited` 加 INDEX_READY 门禁。
3. **build_from_mft 并发下标错位**：final_of 按私有 0 基预编号，但 entries 是全局共享表
   （其他根的 walk 线程并发 push），父链接会指到别的盘的条目。修复：rank_of + base
   偏移，整个 push 阶段持写锁。

另加两道防线：
- **加载抽查**：对每个盘根顶层现枚举（毫秒级），探测到 ≥4 项而索引根下为空 → 拒绝加载触发重建
- **落盘守卫**：盘根顶层为空（枚举异常）的快照拒绝写入，保留旧的好快照

修复后验证：真实快照加载 **1.03s**（347 万条目）→ 即刻就绪 → 搜索命中 250ms。

## 9. 修复轮二（「索引文件不在 exe 同级」，2026-11-15）

用户反馈索引文件未出现在 exe 同级目录。真实运行部署 exe 取证：日志显示落盘守卫
`G:/ 顶层为空（枚举异常），本次跳过落盘` → `索引落盘失败：drive root empty` →
**文件从未写出**。

根因：`$FILE_NAME` 属性字段偏移错误。真实布局为固定头 0x42 字节
（parent@0x00 + 4 时间戳 0x08..0x28 + 2 大小 0x28..0x38 + flags@0x38 + EAs@0x3C），
**名字长度@0x40 / 命名空间@0x41 / 名字@0x42**；解析器与合成测试 fixture 却都按
0x44/0x45/0x46 构造——自洽所以单测全绿，真实卷上 22784 条记录仅 63 条碰巧存活，
卷根子项全丢 → 守卫整单拒写。同时 mtime 改取 0x10（最后修改时间）而非 0x18（MFT
变更时间，语义不符）。

修复与加固：
1. 偏移修正（解析器 + fixture 同步改）；G 盘 63 → 22658 条，卷根子项齐全
2. **MFT 自愈**：直读后卷根零子项 → 自动回退文件夹枚举（`文件夹枚举(MFT回退)`），
   单卷解析异常不再拖死全局落盘
3. 落盘守卫改用已持锁的 inner 内联计数（`root_child_count` 在持锁状态下二次取读锁，
   遇排队写者会死锁——持锁代码禁止再调任何取锁 helper）

修复后实测（真实磁盘）：全库 5 根 3,505,767 条目 → `索引已落盘
D:/wind_app/windFileManger/wfm_index.bin`（153.9MB）→ 重启加载 **1.43s** →
OwnIndex 搜索命中 186ms。

勘误：此前 §6.1 的「636 万条目」系误读——`索引完成 X：N 条目` 打印的是全局累计
`entries.len()`（多盘并发增量入表），C 盘最后完成故其累计值即全库总量，真实全库
≈350 万条目。各盘真实贡献：C≈121 万 / D≈174 万 / E≈29.5 万 / G≈2.6 万 / F≈116。

## §10 修复轮三：$MFT 碎片化导致索引缩水 90%（2026-11-16）

**现象**：管理员运行后索引文件 150MB→16MB，全库条目 350万→33万，G 盘根消失。

**根因链**（三因叠加）：
1. G 盘未接入 → 落盘根集合（5 盘）与当前固定盘（4 盘）不匹配 → 加载拒绝 → 全量重建。
2. **$MFT 大卷必然碎片化**（C=14 碎片/D=9/E=10），原实现假设 $MFT 连续，线性读越过首个连续段（约 140~240MB）后全是无关簇数据 → 签名/fixup 校验失败 → 只解析出 7~13% 条目。F 盘 $MFT 极小无碎片故完整——这就是「F 正确、大盘全缩水」的原因。读取本身无错误（无关簇照常可读），部分数据被当成功返回。
3. 部分条目经孤儿级联剔除（父记录不在已读范围内）后，卷根非空绕过自愈检查，坏快照覆盖好快照（无备份）。

**修复**（`src/mft.rs` + `src/instant.rs`）：
- **碎片感知读取**：先线性读第 0 号记录（必在 $MFT 起始），从其自身 $DATA 属性的 runlist 解码完整碎片映射（`extract_mft_extents`），再按映射读全部记录（`read_extents`）——Everything 同款原理。
- runlist 头字节语义（实证）：低半字节=长度字段尺寸、高半字节=相对 LCN 字段尺寸；长度在前、偏移在后；偏移有符号累积；稀疏运行（osz=0）防御性拒绝。
- 读取不完整/错误 → 返回 None（回退文件夹枚举），**部分数据绝不当成功**。
- **诊断日志落盘** `wfm_index.log`（exe 同级，`flog!` 宏，>4MB 清空重写）——explorer 启动时 stderr 不可见，本次靠它定位根因。
- **快照 .bak 防线**：write_snapshot 落盘前旧文件转 .bak；加载失败时回退 .bak。
- 顺带修正：非驻留 $DATA 真实大小在 0x30（0x38 是 initialized size——常规文件两者相等故从未暴露；0x24 是 4 字节填充）。
- 新增 4 个单测（单碎片/负偏移碎片/非法头/稀疏拒绝），72 全绿。

**教训**：无读取错误 ≠ 读到了对的数据；「解析存活率骤降 + 小盘正常大盘异常」是线性读碎片化数据的指纹。
