# windFileManger 批量处理功能规格（整合 windSAkinfe 批量能力）

> 目标：把 windSAkinfe 的批量文件处理能力以 GUI 形态整合进 windFileManger。
> 算法一律复用 `windsakinfe` 库（path 依赖），不复制实现、不引入新第三方依赖。
> 版本：v1 · 2026-11-14

## 一、范围

| 编号 | 功能 | 状态 |
|---|---|---|
| F1 | 批量重命名（Template 模板引擎） | 本期新增 |
| F2 | 批量计算哈希（SHA-256 汇总复制） | 本期新增 |
| F3 | 批量压缩 ZIP / tar.gz | 已存在（多选已支持），仅回归确认 |
| — | 批量删除 / 复制 / 剪切 | 已存在（Ctrl 多选 + 菜单），不动 |

## 二、F1 批量重命名

### 2.1 入口与前置

- 条目右键菜单（menu-mode 0）新增「**批量重命名**」，动作号 17；工具栏新增「批」按钮（🗑/复/✂ 旁，动作 `batch-selected`），两入口共用 `open_batch_rename`。
- 点击后取**当前 Ctrl 多选集合**；`选中数 < 2` → 红 toast「请先按住 Ctrl 多选至少 2 个条目」并中止（单条目请用「重命名」）。
- 集成测试辅助：环境变量 `WFM_BATCH_MIN=1` 放宽门槛到 1（UI 自动化的 SendInput-Ctrl 无法被 winit 稳定跟踪；真实键盘不受影响，默认行为不变）。
- 参与集合为选中的文件**和目录**（GUI 场景用户勾了什么就改什么，与 CLI `rn` 的"目录自动展开成内部文件"不同——那是目录参数语义，GUI 不适用）。

### 2.2 对话框（dialog-mode = 5）

尺寸 560×420，居中（`root.width/height` 显式定位，遵守 Slint if 容器坑）。

| 区块 | 内容 |
|---|---|
| 标题 | 「批量重命名 — N 个条目」 |
| 模板输入 | LineEdit，默认 `%3d`；`edited` 实时刷新预览 |
| 起始序号 | LineEdit，默认 `1`；非法或空 → 按 1 并在错误行提示 |
| 预览列表 | ListView，行格式 `原名  →  新名`；冲突/错误行红字，未变化行灰字 |
| 错误行 | 模板非法 / 起始序号非法时显示红色一句话 |
| 按钮 | 取消 / 应用（模板非法或预览含错误时「应用」禁用逻辑：仍可点击但被 Rust 端拒绝并红 toast） |

### 2.3 模板语法（与 CLI `rn -t` 完全一致）

复用 `windsakinfe::algo::template::Template`：

| 占位符 | 含义 |
|---|---|
| `%d` `%3d` | 序号（数字，可补零；起始由对话框控制） |
| `%c` `%2c` | 字母序号（a,b,…,z,aa；Excel 列式，1 基） |
| `%s` / `%e` / `%f` | 原 stem / 扩展名 / 全名 |
| `%p` / `%P` | 父目录名 / 相对父路径 |
| `%m` `%H` `%M` `%S` | 修改时间紧凑与时分秒 |
| `%{Y} %{y} %{m} %{d} %{H} %{M} %{S} %{D}` | 修改时间字段；`now:` 前缀取当前时间 |
| `%i` | 文件字节数 |
| `%t` / `%u` | 当前时刻紧凑 / 每条目一次随机 hex6 |
| `%%` | 字面 `%` |
| `*` | **GUI v1 不支持**（无 pattern 捕获输入）→ 模板含裸 `*` 直接判非法 |

不自动补扩展名（与 CLI 行为一致；要扩展名请写 `%e` 或模板里带点）。

### 2.4 渲染规则

- 条目按**列表当前排序顺序**编号，seq 从「起始序号」起、步长 1。
- `RenderCtx`：`captures=[]`、`mtime`=文件修改时间、`size`=文件大小、`now`=当前时刻、`rand`=每条目一次 `rand_hex(6)`。
- 渲染结果为空串 → 该行红字「渲染出空名字」。
- 渲染结果与原名相同（同目录）→ 该行灰字「（不变）」。
- **冲突判定**（预览阶段）：新名与以下任一重名（Windows 语义不分大小写，比较用 `to_lowercase`）即标红：
  1. 同目录内**不参与改名**的既有条目；
  2. 本批**其他条目**渲染出的新名（重复模板名互撞）。
  - 条目自身原名不算冲突。

### 2.5 应用执行

- 后台线程逐条 `fs::rename`：
  - 目标已存在 → 跳过（与 CLI `--on-conflict skip` 一致；预览已标红提醒用户改模板）；
  - 其他 IO 错误 → 记失败原因。
- 执行前整体快照参与集合；逐条以**执行时刻**的磁盘状态为准。
- 完成后刷新列表 + toast：
  - 无失败：绿「批量重命名完成：X 成功 / Y 跳过」；
  - 有失败：红「批量重命名：X 成功 / Y 跳过 / Z 失败（首个原因）」。

## 三、F2 批量计算哈希

- 动作号 16（「计算哈希」）扩展：
  - 选中 **1** 项：保持现有行为（CRC32/MD5/SHA-1/SHA-256 四算法复制剪贴板）。
  - 选中 **≥2** 项：后台逐个流式计算 **SHA-256**（1 MiB 块），完成后按 `文件名<TAB>sha256` 每行一条写入剪贴板；绿 toast「已计算 N 个文件的 SHA-256 并复制到剪贴板」。
  - 单个文件计算失败 → 该行写 `<文件名>  <错误原因>`，toast 改红并列出失败数。

## 四、实现约束

1. `src/sakinfe.rs` 新增（全部带单测）：
   - `pub struct RenameItem { pub path: PathBuf, pub new_name: String }`
   - `pub struct RenameOutcome { pub ok: u32, pub skipped: u32, pub failed: u32, pub first_err: Option<String> }`
   - `pub fn batch_rename(items: &[RenameItem]) -> RenameOutcome`（skip 语义：目标已存在；不覆盖）
   - `pub fn hash_files_sha256(paths: &[PathBuf]) -> Vec<(String, Result<String, String>)>`
   - 预览与执行共用同一渲染函数，避免预览/结果不一致：`pub fn render_batch(paths: &[PathBuf], tpl: &str, start: u64, names_in_dir: &HashSet<String>) -> Result<Vec<PreviewRow>, String>`
2. UI：`ui/app.slint` — menu-mode 0 加第 11 项（高度 348→382px，PopupWindow y 钳制 366→400px）；dialog-mode=5 新对话框；Logic 新增 `batch-rows` 模型、`batch-preview(tpl, start)`、`batch-apply(tpl, start)` 回调。
3. `main.rs`：menu-action 加 17 分支；dialog-ok 按 mode 5 分发。
4. 不新增依赖；`cargo test` 全绿 + `clippy -D warnings` 零告警 + release 构建通过。

## 五、验收标准

1. Ctrl 多选 3 个文件 → 右键「批量重命名」→ 模板 `%{Y}%{m}%{d}_%3d` → 预览显示 3 行日期+序号新名 → 应用 → 列表刷新、toast 报成功数、磁盘文件名符合模板。
2. 模板 `不存在{%` 等非法输入 → 预览区红字报错，「应用」被拒。
3. 模板渲染出与既有文件重名的目标 → 对应行红字，应用后该条被跳过且计入 toast。
4. 多选 2 个文件 → 「计算哈希」→ 剪贴板两行 `名字<TAB>sha256`，哈希值与已知标准值一致。
5. 多选目录+文件混合 → 均参与改名，目录改名后其内容不受影响。
